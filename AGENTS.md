# Project conventions

- Use English for new project names, filenames, documentation, code comments,
  application text, commit messages, issues and pull requests unless the user
  explicitly requests another language.
- Communicate with the user in German unless requested otherwise.
- Preserve intentional multilingual test fixtures and external MediaPortal
  schema identifiers; do not translate test data if that changes the behavior being tested.
- The owner requested public visibility on October 20, 2026. Keep the repository
  public; change its audience only at the owner's explicit request.
- Commit and upload completed development milestones, and keep STATUS.md current.
- Work in larger coherent blocks with concise progress updates. Do not end the
  turn after every small validated change; pause for a real blocker or a
  substantial completed milestone.
- Distinguish historical test reports from newly executed validation.
- Use isolated skin copies and preserve original skin files.
- The owner reauthorized attended Windows app automation on October 19 after the
  earlier hard-reset incident. Use current observations, avoid repeated failed
  input attempts, and let the owner complete permission prompts and native
  dialogs when Computer Use cannot target them. DirectX replacement remains deferred.

- Start future projects in English with a private GitHub repository from the beginning,
  and record their current state and remaining work there.

- Work in substantial blocks; run necessary validation at milestones rather than after every edit. Avoid repeating successful checks without a relevant change. Make routine implementation decisions independently and keep progress reports concise.

- Continue routine follow-up work without asking for another continuation prompt. Pause only at a substantial integrated milestone, a genuine blocker, or the owner's request; keep updates brief and combine implementation, validation, documentation and GitHub delivery.
